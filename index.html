    Macchina virtuale

    Creare e configurare una macchina virtuale con Ubuntu 20.04

    1. Aprire l'interfaccia web di VMWare ESXi
    2. Creare una nuova macchina
    3. Assegnare risorse adeguate (es. 4096MiB di RAM, 40GiB di spazio su disco fisso)
    4. Selezionare l'ISO di Ubuntu dallo storage delle ISO

    Installare Ubuntu

    1. Far partire la macchina virtuale
    2. Seguire le istruzioni a video, senza installare software aggiuntivo se richiesto
    3. Al momento opportuno (configurazione delle interfaccie di rete) disattivare l'impostazione con DHCP e inserire i parametri indicati dal responsabile della rete
    4. Configurare OpenSSH (installarlo quando richiesto e permettere l'accesso con username)
    5. Riavviare

    Accedere via SSH

    A questo punto possiamo accedere con Putty via SSH. Inserire i seguenti dati:

    • Indirizzo IP precedentemente configurato
    • Porta 22

    e schiacciare "Open". Inserire poi utente e password configurati nel SO

    Aggiornare le repository

    Dobbiamo rimuovere la repository del CD di installazione, altrimenti il sistema operativo proverà a cercare i nuovi pacchetti da installare anche lì.

    Link alla question su AskUbuntu

    Eseguire i seguenti comandi CLI

    sudo nano /etc/apt/sources.list

    nell'interfaccia che si apre aggiungere un cancelletto # davanti alla riga che si riferisce al CD (contiene la scritta cdrom).

    Installare mailcow (versione dockerized)

    Guida ufficiale

    Installare Docker

    Docker è un software che permette di creare e gestire container, ovvero sistemi virtualizzati solo "sopra" il kernel, che non devono emulare tutta la macchina a partire dall'hardware.

    Mailcow usa Docker per permettere una gestione più facile delle dipendenze del software, dato che un software mail è molto complesso e necessita di molti altri software alla base per funzionare. Gestire tutte le dipendenze manualmente sarebbe molto laborioso.

    Eseguire i seguenti comandi:

    Installiamo Docker curl -sSL https://get.docker.com/ | CHANNEL=stable sh e abilitiamolo subito e a ogni riavvio systemctl enable --now docker

    A questo punto possiamo iniziare a usare Docker. Prima però installiamo un plugin, "Docker Compose", che ci permetterà di "orchestrare" i vari container e gestirli assieme. Mailcow infatti funziona con più container autonomi che comunicano tra loro via socket appositi.

    apt update apt install docker-compose-plugin

    Configurare mailcow

    Da questo momento in poi opereremo in modalità root (anche detta amministratore o superuser)

    su

    Così entriamo in modalità amministratore (nei comandi è contrassegnata, come da convenzione, con un cancelletto)

    umask

    Verifichiamo che l'output sia 0022 per controllare di avere i permessi giusti

    0022

    Entriamo nella cartella designata per l'installazione di software utente

    cd /opt

    Cloniamo la repository contenente il codice di Mailcow (scarichiamo il sorgente del programma)

    git clone https://github.com/mailcow/mailcow-dockerized

    Entriamo nella cartella dove è stato scaricato

    cd mailcow-dockerized

    Creiamo la configurazione di base del software

    ./generate_config.sh

    Quando verrà chiesto a schermo dovremo inserire un Fully Qualified Domain Name per accedere poi al server

    Infine, facciamo partire con Docker tutta l'infrastruttura

    docker compose pull docker compose up -d

    Ora Mailcow è partito e pronto per essere usato!

    Accesso al server Mailcow da un altra macchina e configurazione finale

    Ora, per completare la configurazione, accediamo a Mailcow attraverso l'IP del server da un'altra macchina

    Inseriamo l'IP su un qualsiasi browser e accediamo con le credenziali admin (come utente) e moohoo (come password)

    Bisogna accedere con HTTP, controllare che l'URL specifichi il protocollo giusto (non HTTPS)

    In alternativa, accedendo con HTTPS, bisogna impostare il sistema in modo che si fidi dei nostri certificati self-signed, ma non essendo necessario tralasciamo questo passaggio

    A questo punto possiamo seguire il video tutorial (che copre comunque anche le parti precedenti) in quanto spiegare testualmente la parte di configurazione attraverso la GUI web sarebbe tedioso e il risultato sarebbe difficle da seguire.

    Configurare file degli host di Windows

    Questa parte è riportata anche testualmente per avere una maggiore chiarezza rispetto a cosa va inserito nel file da modificare

    Ora dobbiamo configurare Windows in modo che mandi le richieste relative al FQDN scelto prima direttamente all'IP della macchina virtuale senza che ci sia un server DNS che risolve effettivamente il nome del dominio

    Apriamo il file C:\Windows\System32\Drivers\etc\hosts

    Inseriamo il seguente testo in coda:

    192.168.1.1 fqdn.scelto.prima.in.configurazione

    dove al posto di 192.168.1.1 bisogna sostituire l'IP della macchina virtuale e al posto di fqdn.scelto.prima.in.configurazione l'FQDN con il quale si vuole accedere al server.

    Inoltre inseriamo anche un'altra riga identica ma al posto dell'FQDN per accedere al server inseriamo quello che sarà il dominio della mail (la parte dopo la chiocciola, @).
